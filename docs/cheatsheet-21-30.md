### curl 发带参数的 GET / 取证据

| 命令 | 干什么 | 英文全称 | 记忆钩子 |
|------|--------|---------|---------|
| `curl -s 网址` | **静默**：不打印进度条（只出正文） | **s**ilent | silent = 安静 |
| `curl -s -o 文件 网址` | 把响应**存成文件**（之后随便查） | **o**utput | out = 输出到文件 |
| `grep -o "关键词.\{0,20\}" 文件` | **只打印**匹配到的那一段（前后各 20 字符） | **o**nly matching | only = 只留匹配的 |
| `grep -n "关键词" 文件` | 打印整行 + 行号 | **n**umber | number = 行号 |
| `curl -G -d "search=x" 网址`（选学） | 把数据**拼到 URL 的 query** 上（GET 用） | **G**ET | `-G` 走 GET |
| `curl --data-urlencode "search=<x>"`（选学） | **自动替你做 URL 编码** | — | 「替你做 % 转义」 |

> ⚠️ **同一个字母，两个工具两个意思**：`curl -o` = **output 存文件**；`grep -o` = **only matching 只打印匹配**。别混。

### URL 编码对照（手写 payload 必背）

| 原字符 | 编码 | 说明 |
|--------|------|------|
| `<` | `%3C` | 开标签的钥匙 |
| `>` | `%3E` | ⚠️ 和 `%3D`（`=`）只差一个字母，**ASCII 里 0x3D/0x3E 挨着**（D 在 E 前、`=` 在 `>` 前） |
| `"` | `%22` | 双引号（`alert("Q")` 要它） |
| `'` | `%27` | 单引号 |
| `(` `)` | `%28` `%29` | 函数括号 |
| `=` | `%3D` | 等号（也常用在 `name=value` 里，query 分隔符除外可不编） |
| 空格 | `+` 或 `%20` | query 里 `+` 就是空格（`unquote_plus` 才认它） |
| `%` | `%25` | 百分号自己 |

### 两个自检习惯（Day 21 最大的收获）

| 什么时候 | 敲什么 | 为什么 |
|---------|--------|--------|
| 拼**长命令 / 带特殊字符**的命令前 | `echo "你的那串东西"` | 先看 **shell 解析后真正送出的是什么**（引号、`<` `>` 有没有被吃掉） |
| 手写完 URL 编码后 | `python3 -c "from urllib.parse import unquote_plus; print(unquote_plus('...'))"` | **反解对账**：解出来和你原本想写的是不是同一句 |

> 三层解析要分清：**shell（引号/重定向）→ URL 编码（URL 允许哪些字符）→ JS 语法（要不要引号）**。
> 一个字符之差 = 「能执行」和「报错」之差。

### ⚠️ 坑（Day 21 实录）

- **`"` 直接写在 curl 的双引号里** → 被 **shell** 吃掉 → payload 退化成 `alert(Q)` → `ReferenceError: Q is not defined` → **不弹窗**（与 Day 20 `alert(Qzl)` 同族，只是这次是 shell 干的）。
  → 解药：`"` 编码成 `%22`，URL 里就没有真引号了，外层双引号才安全。
- **`%3D` 当 `%3E` 用** → `<img ...>` 没闭合，浏览器把后面的 `'</h1>` 也吞进属性值 → `onerror=alert("Q")=` → `SyntaxError`。
- **`onerror.("Q")`（把 `=` 打成 `.`）** → 处理函数名不对，事件不触发。
- **弹窗没出现 ≠ 没执行** → `F12` → **Console** 看红字（Day 20 同款）。
- **横幅 Not solved ≠ 没解开** → 钩子已上报，等 5–10 秒或 `F5` 刷新再看。
- **lab 页面的 Solution 折叠框**：做题时别点，自己解出来才算数。
- **curl 看到的 ≠ 浏览器看到的**：curl 拿到的是**服务器原文**（标签未被解析），浏览器给的是**解析后的成品**。写报告时两个视角都要。
- **注册账号只影响"记录进度"**，不影响能不能打 lab（官方原话：access everything for free, track progress by creating an account）。

### 🔎 Day 21 的核心一句话

> **上下文（context）决定 payload 怎么写；`nothing encoded` 决定了「原样放行」——两个条件同时成立，才有 XSS。**
> 防御加在**输出层**：`<` 变 `&lt;` 之后，浏览器只会把 payload「念」给用户看，不执行。

## Day 22 · 存储型 XSS（Stored XSS）：一次投放，全员中招

### 三种 XSS 对照（考试/报告都用这张）

| | **Reflected**（反射型） | **Stored**（存储型） | **DOM-based**（DOM 型） |
|---|---|---|---|
| 数据存不存 | 不存，当场回显 | **存进服务器**（数据库/文件） | 不经过服务器，页面 JS 自己读自己写 |
| 谁中招 | 点了那条链接的人 | **所有访问该页面的人**（含管理员） | 点了那条链接的人（但毒在执行发生在浏览器） |
| 证据在哪 | URL 的 query 里 | **响应正文里** | 只有 F12 Elements 有，`Ctrl+U` 搜不到 |
| 修的时候 | 输出编码 | 输出编码 | **改 JS**（别用 `innerHTML`，用 `textContent`） |

### 两个必须分清的"点"

| 名词 | 人话 | 今天的例子 |
|---|---|---|
| **输入点**（input point / entry point） | 数据**塞进去**的地方 | 评论表单 4 个字段：comment / name / email / website |
| **输出点**（output point / sink） | 数据**吐出来**、拼进 HTML 的地方 | 文章页的评论列表 |

> **输入点 ≠ 输出点**：Stored 型的这两个点**不在同一个请求、不在同一个页面**里。这就是它和 Reflected 的结构差别。

### 判断 Stored 的三招（写报告就靠这三句）

| # | 动作 | 如果是 Stored |
|---|---|---|
| 1 | 关掉页面重开 / 换无痕窗口 / 换浏览器 | 照样弹 |
| 2 | 看地址栏 | **干净**，不带 payload |
| 3 | `curl` 请求干净 URL → `grep` 响应正文 | 正文里**能找到** payload |

> 「有输入点」≠「存储型」。搜索框也有输入点，但通常是 Reflected。
> 判据只有一条：**数据有没有被存下来？输出点是不是在另一个请求里？**

### 取证命令

| 命令 | 干什么 | 说明 |
|------|--------|------|
| `curl -s "网址/post?postId=10" -o /tmp/post.html` | 请求一个**干净的 URL**，把响应存下来 | `postId` 是文章编号，从文章页 URL 抄 |
| `grep -o "onerror.\{0,30\}" /tmp/post.html` | 在响应正文里搜 payload | 搜到了 = 服务器在发毒 = Stored |

### 三层「限制」，谁在拦你？

| 层 | 写在哪 | 例子 | 谁执行 | 能绕吗 |
|---|---|---|---|---|
| ① 输入框属性 | HTML 标签上 | `maxlength="10"`、`required` | **浏览器** | ✅ F12 删 / `curl -d` 直接发 |
| ② 页面 JS 校验 | `<script>` 里 | `if (含"<") alert("不许")` | **浏览器** | ✅ 不执行 JS / 改 JS |
| ③ 服务端代码 | PHP/Python，看不见 | `if (strlen($name) > 10) die();` | **服务器** | ❌ 只能找逻辑漏洞 |

> 判据一句话：**这段代码在哪跑？浏览器里 → 攻击者可改；服务器上 → 改不了。**
> 所以 **XSS 的正解只能做在 ③**：输出编码。前端过滤 = 只锁住你自己的浏览器。

### 两个模型（今天最有价值的两句）

> **表单只是「填表助手」**：帮你把内容拼成一个请求发出去。
> **服务器只相信「收到的那个请求」**，从不回头看页面上的表单。
>
> **curl 不管表单长什么样，但必须遵守服务器的数据契约**（字段名 `name=value` 写错 = 丢字段）。

### ⚠️ 埋雷：`type="hidden"` 不是安全措施

```html
<input type="hidden" name="role" value="user">
```

浏览器里看不见，但**会被提交**；服务器要是直接信了 → 改成 `role=admin` 就是越权。
→ 阶段二的 **IDOR / 越权 / 业务逻辑漏洞** 全从这里起。

### HTML 实体（entity）对照 —— 服务器做输出编码时干的事

| 原字符 | 实体 | 说明 |
|--------|------|------|
| `<` | `&lt;` | 标签开不出来了 |
| `>` | `&gt;` | 标签关不上了 |
| `"` | `&quot;` | 引号逃不出属性了 |
| `'` | `&#39;` | 同上（单引号版） |
| `&` | `&amp;` | 和号本身 |

> 在 `curl` / `Ctrl+U` 里看到 `&lt;` `&quot;` = **这个字段做了编码**；看到原字符 = **nothing encoded**。
> 同一个表单，不同字段的处理**可以不一样** —— 必须逐字段试。

### F12 Elements vs Ctrl+U（证据铁律）

| | 看到什么 | 用来干嘛 |
|---|---|---|
| **`Ctrl+U`** | 服务器发来的**原始字节** | **取证**（判断有没有编码、payload 在不在正文里） |
| **F12 Elements** | 浏览器解析后、**活着的 DOM**（被 JS / 扩展 / 翻译插件改过） | 定位结构、看执行结果、Console 看报错 |

> ⚠️ 见过 `<font _msthash=... _msttexthash=... _mstmutation=...>` 吗？`mst` = **Microsoft Translator**（Edge 翻译功能）注入的，`_istranslated="1"` 直接告诉你这是译文。**不是网站写的**，别写进报告（真实误报来源）。
> 做靶场/取证前先关掉自动翻译。

### ⚠️ 坑（Day 22 实录）

- **把 F12 Elements 当源码** → 看到 `_mst*` 一堆莫名属性，以为网站有问题。取证一律 `Ctrl+U` / `curl`。
- **只试一个字段就下结论** → comment 原样输出能打通，name 被编码打不通；**同一表单逐字段试**。
- **`alert(Qzl)` 少引号**（第 2 次）→ `ReferenceError: Qzl is not defined` → 不弹窗；判据看 F12 Console。
- **以为"有输入点就是存储型"** → 搜索框也有输入点，是 Reflected。判据是「有没有存下来」。
- **以为前端 `maxlength` / JS 校验是修复** → 只锁浏览器；`curl -d` 直接发就绕过去了。
- **想靠"过滤输入"修 XSS** → 黑名单永远漏、富文本还要 `<`；正解是**输出编码**。

### 🔎 Day 22 的核心一句话

> **毒存在服务器上，URL 干干净净也能中招；判 Stored 看三样——重开还弹、URL 干净、正文里有 payload。**
> **修复永远做在服务端输出层：数据怎么存都行，吐进 HTML 的那一刻按位置转义。**

## Day 23 · 属性上下文（attribute context）：不用标签也能跑

### 三种「格子」（context）—— payload 是照着格子现写的

| 格子 | 长什么样 | 你写的 `<` `>` 是什么身份 | 逃出去需要什么 | 逃出去之后能写什么 |
|---|---|---|---|---|
| **A 标签之间** | `<p>这里</p>` | 就是标签语法 | 不用逃 | **新标签**（`<img src=x onerror=...>`） |
| **B 属性值里** | `value="这里"` | 只是属性值的内容，**没有标签权力** | 一个**没被编码的引号** | **新属性**（`on...="..."`） |
| **C JS 字符串里** | `var s = "这里";` | 普通 JS 字符（`<script>` 内部不解析标签） | JS 的引号 | **JS 代码**（`alert(1)`） |

> 判 context 只做两件事：① 我的输入落在哪个格子 ② 这个格子需要的「开门字符」服务器编码了没有。

### 关键模型：一个标签 = 一排属性，空格隔开

```html
<input type="text"  value=""  onmouseover="alert(1)"  size="80">
       属性1         属性2      属性3（注入进来的）       属性4
```

- 浏览器在 `<input` 到 `>` 之间**一路读「属性名=属性值」**，空格分隔，数量不限。
- 所以**属性注入完全不需要 `<` `>`**：关门（`"`）+ 空格 + 新属性。
- `onerror` / `onclick` **本身就是属性** —— Day 15 的 `<img src=x onerror=alert(1)>`，执行的是属性，不是标签。

### 事件属性表（挑事件 = 挑「怎么被叫醒」）

| 属性 | 什么时候执行 | 页面加载后要人做什么 |
|---|---|---|
| `onclick` | 点它 | 点一下 |
| `onmouseover` | 鼠标**移上去** | 移过去 |
| `onfocus` | **获得焦点** | 点进去 **或** 靠 `autofocus` 自动 |
| `oninput` | 在框里**打字** | ⚠️ 页面加载时不会发生 → 永远不执行 |
| `onload` | 加载完成 | 只有 `body`/`img`/`script` 有，`input` 没有 |
| `onerror` | 加载失败 | `img src=x` 必然失败 → 自动触发 |

**`autofocus`** = HTML **布尔属性**（只写名字、不写值）：页面加载完自动把焦点给这个元素。
`autofocus` + `onfocus` = **零交互弹窗**（PoC 可信度最高；`onmouseover` 得指望受害者正好把鼠标移过去）。

### 引号三层规则（写 payload 时按这个对）

```html
name=search  value="  "  onmouseover="  alert('1')  "  >
              └──┬──┘    └──────┬─────┘  └───┬────┘ └┘
            模板的引号      你属性值的引号   值内字符串  服务器补的收尾引号
            （被你关掉）    （必须成对）     （用单引号）
```

1. 外层是双引号 → 你的「关门」也用双引号（`value=""`）
2. 新属性的值外面用**同一对**引号（`onmouseover="..."`）
3. 值**里面**的字符串用**单引号**（`alert('1')`）或数字不加引号（`alert(1)`）
4. 不确定后面紧跟什么时，**少写收尾引号**，让模板那份替你关

### ASCII / URL / HTML 实体对照（手写 payload 必查）

| 字符 | 十进制 | 十六进制 | URL 编码 | HTML 实体 |
|---|---|---|---|---|
| `"` | 34 | 0x22 | `%22` | `&quot;` |
| `'` | 39 | 0x27 | `%27` | `&#39;` |
| `(` | 40 | 0x28 | `%28`（query 里可原样写） | — |
| `)` | 41 | 0x29 | `%29`（query 里可原样写） | — |
| `+` | 43 | 0x2B | `%2B` | — |
| `&` | 38 | 0x26 | `%26` | `&amp;` |
| `%` | 37 | 0x25 | `%25` | — |
| `<` | 60 | 0x3C | `%3C` | `&lt;` |
| `=` | 61 | 0x3D | `%3D` | — |
| `>` | 62 | 0x3E | `%3E` | `&gt;` |
| 空格 | 32 | 0x20 | `%20`（或 `+`） | — |

> 规律：**`%XX` = ASCII 码的十六进制**，会查 ASCII 就能自己推。
> `+` 在 query 里表示空格，所以真的是加号时必须写 `%2B`。

生成与对账（不用手算）：

```bash
python3 -c "from urllib.parse import quote; print(quote('\" onmouseover=\"alert(1)'))"
# → %22%20onmouseover%3D%22alert%281%29
python3 -c "from urllib.parse import unquote_plus; print(unquote_plus('%22%20onmouseover%3D%22alert%281%29'))"
# → " onmouseover="alert(1)
```

### curl 排错三件套（+ 状态码对照）

| 症状 | 真实原因 | 解法 |
|---|---|---|
| 什么都没输出，`grep` 也不报错 | 文件生成了但是**空的**（请求失败） | 加 `-sS` 看错误；`wc -c` 看大小 |
| `grep: No such file or directory` | curl 没跑成功，文件没生成 | 先看退出码 `echo $?` |
| `curl: (16) ... SETTINGS frame` | HTTP/2 协商坏了 | 加 `--http1.1`（永久：`echo '--http1.1' >> ~/.curlrc`） |
| 请求发不出去 | URL 里有**裸空格** | 空格写 `%20` |
| `This lab is not accessible over HTTP` | 用了 `http://` | 换 `https://` |

| 状态码 | 意思 | 下一步 |
|---|---|---|
| `200` | 正常拿到页面 | 看内容 |
| `404` | 路径/参数名不对 | 抄 `<form action>` / `<input name>` |
| `405` | 路径存在但不收这个方法 | 换 GET/POST |
| `504` | 网关连不上后端 | lab 实例休眠 → `Back to lab` 重置 |
| `000` | 压根没回话 | 查网络 |

取证标准动作：

```bash
curl -sS --http1.1 -o /tmp/x.html -w 'HTTP=%{http_code} SIZE=%{size_download}\n' "https://实例/?search=$P"
grep -n 'value=' /tmp/x.html
```

> 先看 `-w` 那两个数字（`200` + 几千字节 = 真拿到页面；`197` = 错误页；`0` = 没写进去），再 grep。

### ⚠️ 坑（Day 23 实录）

- **猜参数名 / 猜路径** → 用了 Day 21 的 `searchTerm`，这个 lab 是 `name=search`、`action=/` → 404。**参数名抄 `<input name>`，提交目标抄 `<form action>`。**
- **`oninput` 不会自己触发** → 它等「打字」；页面加载时值已填好 → 属性挂上了但永远不被叫醒。
- **属性值不加引号** → `oninput=alert("1")` 渲染成 `oninput=alert("1")"`，值里混进多余引号 → `SyntaxError`。
- **双引号套双引号** → `onmouseover="alert("1")"` → 值被切成 `alert(`（未闭合）→ 死。值内字符串用**单引号**。
- **`curl -s` 吞掉错误** → 误判成「没输出」，其实是静默失败。
- **URL 里写裸空格** → 请求根本没发出去。
- **`grep "hi"` 命中错误页的 `This`** → 关键词写长（`qzl12345`、`value=`）。
- **同一参数、两个输出点、编码规则不同**（本 lab：`<h1>` 里连 `"` 都编码，`value=` 里 `"` 原样）→ 必须**逐输出点**判。

### 🔎 Day 23 的核心一句话

> **payload 不是背出来的，是照着格子现写的：先判格子 → 找「开门字符」→ 逃出去之后按那个格子能写的东西写（标签 / 属性 / JS）。**
> **尖括号被编码 ≠ 没戏：属性本身就是另一个代码区。**

## Day 24 · JavaScript 字符串上下文（JS string context）：转义符的两面

### 第三种格子长什么样

```html
<script>
var searchTerms = '你的输入';
</script>
```

- `<script>` 内部**换了一台解析器**：HTML 标签规则全失效，`<img>` 只是 6 个普通字符
- JS 解析器在字符串里只认两件事：字符串从哪开始、到哪结束。开始是 `'`，结束是**下一个没被吃掉的 `'`**
- 所以这一格：`<` `>` `"` 全是普通字符；**只有 `'` 和 `\` 有权力**

### 核心模型：`\` 会「吃掉」下一个字符

解析器脑子里两句话：

> ① 吃到 `\` → 必须再多吃紧跟的一个字符，两个一起变成**一个普通字符**
> ② 吃到 `'` 且前面没有 `\` 领着 → **字符串结束**

| 源码里写的 | 怎么吃 | 内容是什么 |
|---|---|---|
| `\'` | `\` + `'` | 一个普通 `'` |
| `\\` | `\` + `\` | **一个普通 `\`** |
| `\\\'` | 两对，各吃各的 | `\'` 两个字符 |

> 关键：**`\\` 不保护后面的东西**。它俩互相吃掉、变成内容里的一个反斜杠，然后就耗尽了。
> 字数验证（Console）：`'a\\b'.length` = **3**（源码 4 个字符，内容只有 3 个）。

### 同一种「转义」有两种配置，打法完全相反

| 服务器配置 | lab 名字（看名字选打法） | 结果 | payload |
|---|---|---|---|
| `'` 和 `\` **都**转义 | `...single quote **and backslash** escaped` | 字符串路线**死**（每个 `'` 都被喂了 `\`） | 掀桌子：`</script><script>alert(1)</script>` |
| `'` 转义，`\` **不**转义 | `...angle brackets and double quotes HTML-encoded **and single quotes escaped**` | 自带的 `\` 顶掉服务器那颗盾 | `\';alert(1)//` |

**两个 lab 名字只差几个词，payload 完全相反。先读 lab 名，再选打法。**

### `//` 注释：收拾「孤儿」

提前闭合字符串后，模板尾巴上的 `';` 会变成孤儿：

```javascript
var searchTerms = '\\';alert(1)';    ← 没有 // 就死在这
                              ↑
                    孤儿 ' 要开新字符串，行尾没闭合
                    → SyntaxError → 整行作废（alert 也不执行）
```

`//` = 从这里到行尾全是注释。加上它，孤儿被吃掉，整行合法。

**语法错误是「整行作废」，不是「错的那部分作废」——所以 `//` 是必需品。**

### 三种「编码」别混

| 层 | 谁做的 | 长什么样 | 活到哪 |
|---|---|---|---|
| **URL 编码** | 浏览器 / curl | `%22` `%3C` | **路上**，服务器一进门就解码 |
| **HTML 实体编码** | 服务器输出时 | `&quot;` `&lt;` | **落地**，真写进 HTML |
| **JS 字符串转义** | 服务器输出时 | `\'` `\\` | 落地，进 `<script>` 里 |

> 口诀：`%XX` 是快递包装，进门拆掉；`&xxx;` / `\'` 是货本身换了零件，拆不掉。

### 出口：掀桌子（`</script>`）

```html
<script>
var searchTerms = '</script><script>alert(1)</script>';
```

- HTML 解析器在 script 内部**只对 `</script` 敏感**（不然它出不来）
- `</script>` 一出现 → script 元素当场结束 → 后面就是 HTML 地面
- 残留的 `';` 变成页面文字（无害）
- Console 会有一条 `SyntaxError`（被截断的 `var searchTerms = '`）——**正常，别管**：HTML 先把页面切完，后面的 script/img 已经执行了
- **证据**：页面上出现 `' document.write(")` 这种残留文字，就说明 `</script>` 真的生效了

### 手写 payload 的高危区（个人实录）

| 高危对 | 症状 |
|---|---|
| `%3D`(`=`) / `%3E`(`>`) | 差一个字符，标签没闭合 |
| `=` / `(` | `alert=(1)` = 赋值不是调用，不报错也不弹 |
| 缺 `/` | 把 `<script>` 当 `</script>` 用（开始 ≠ 结束） |
| 全角 `（）` `！` | 到服务器成了真全角 → SyntaxError |

> 提交前自检：`python3 -c "from urllib.parse import unquote_plus; print(unquote_plus('...'))"` 反解出来肉眼过一遍。

### ⚠️ 坑（Day 24 实录）

- **只验「落地长相」就当「能执行」** → 源码里有 payload ≠ 它跑得起来。**判据永远是弹窗 / Console，不是 grep。**
- **以为 `\\` 能保护后面的 `'`** → 它俩互吃，谁都保护不了
- **`alert=(1)`** → 赋值不是调用，静默失败（连报错都没有）
- **把 `//`（JS 注释）和 `</script>`（HTML 标签）混成一件事** → `//` 只在 **JS** 里有效，**管不到 HTML 标签**；`</script>` 是 **HTML 解析器**处理的。两层各管各的，别拿一层去"解释"另一层
- **把两个 lab 的打法记串** → 看 lab 名字里「backslash」有没有被 escaped
- **Elements 里看着像文字就断定没执行** → 要看页面有没有残留的 `document.write(` 这类文字，那才是 `</script>` 生效的证据

### 🔎 Day 24 的核心一句话

> **`\` 会吃掉下一个字符；哪些字符被喂了 `\`，决定这一格还能不能出门。全被喂了，就换格子——`</script>` 是永远的备用门。**
> **而且：验证 payload 的唯一判据是「它跑了没」，不是「它在源码里长什么样」。**

## Day 25 · DOM 型 XSS（DOM-based XSS）：服务器从没见过你的 payload

### 三类 XSS 的分水岭（精修版）

| 类型 | 服务器拼过吗 | 存下来了吗 | `Ctrl+U` 搜得到吗 |
|---|---|---|---|
| Reflected | ✅ 当场拼进响应 | ❌ | ✅ |
| Stored | ✅ 从库里取出来拼 | ✅ | ✅ |
| **DOM** | **❌ 只发死页面** | ❌ | **❌** |

> 「`Ctrl+U` 搜得到」只能**排除** DOM，**分不出** R 和 S —— 还要看「关页面重开还弹吗 / 地址栏干净吗」（Day 22 三招）。
> **一条判据只划一条线。**

### 三个「把手」：window / document / location

| 对象 | 管什么 |
|---|---|
| `window` | 整个标签页；所有全局东西都挂在它身上 |
| `document` | 页面内容（DOM 树） |
| `location` | **地址栏**（只反映、不判断） |

`window` 的属性可直接当全局变量用，所以 `location` ≡ `window.location`。

### 地址栏拆解（`location` 字段）

```
http://localhost:8083/dom_search.html?q=hello#top
└┬─┘   └────┬─────┘└──────┬───────┘└──┬───┘└┬─┘
protocol   host         pathname    search  hash
```

| 字段 | 内容 | ⚠️ |
|---|---|---|
| `location.href` | 整个地址栏 | |
| `location.search` | `?q=hello` | **带着 `?`** |
| `location.hash` | `#top` | **带着 `#`，而且浏览器不发它给服务器** |

### source 图鉴（攻击者能控制的入口）

| source | 是什么 | 谁能让它变 |
|---|---|---|
| `location.search` | `?` 后面那段 | 发链接的人 |
| `location.hash` | `#` 后面那段（**不发服务器**） | 发链接的人 |
| `document.referrer` | 从哪个页面跳来的（= HTTP 头 `Referer` 的 JS 版） | 放链接的人 |
| `window.name` | 跨页面还活着的字符串（同标签页） | 先打开的攻击者页面 |

> ⚠️ 拼写：HTTP 头是 `Referer`（历史拼错），JS 属性是 `referrer`（拼对了）。

### sink 图鉴（把字符串当代码 / HTML 处理的地方）

| sink | 危险点 |
|---|---|
| `innerHTML` | 字符串当 HTML 解析 |
| `document.write` | 同上；写在当前脚本位置，**页面加载完后调用会清空整个文档** |
| `eval("字符串")` | 字符串当 **JS 代码**执行 |
| `setTimeout("字符串", n)` | 第一个参数给字符串时按代码执行 |
| `setAttribute("src" / "href", v)` | 值为 `javascript:` 时执行 |

> 判据：**会把字符串当「语法」解析的 = sink；只当文字（`textContent`）= 不是。**

### 两个「传送门」：把数据送进 HTML 解析器

```js
document.write(字符串)         // 数据 → HTML 源码
element.innerHTML = 字符串     // 数据 → HTML 源码
```

倒进去之后，数据**立刻变成语法**，由 HTML 解析器重新读一遍。

### 三种「放法」，三条命（总纲）

| 放法 | 服务器怎么写 | 谁读它 | payload 身份 | 要算什么 | 例子 |
|---|---|---|---|---|---|
| A 放进 HTML 标签间 | `echo "<p>".$_GET['q']."</p>"` | HTML 解析器 | HTML 源码 | 标签结构 | `"><img src=x onerror=alert(1)>` |
| B 放进 `<script>` 的字符串 | `echo "var q='".$_GET['q']."';"` | JS 引擎（在字符串里） | **JS 源码** | 转义 / 吃掉模型 | `</script><script>alert(1)</script>` |
| C 服务器不拼、页面 JS 自己取 | 死页面 + `'...' + query + '...'` | 先 JS（当数据）→ 再 HTML | 数据 → HTML 源码 | 标签结构 | `"><img src=x onerror=alert(1)>` |

> **写 payload 前先问：我的字符串最后是被谁、当什么读的？**

### 「谁在读」决定字符含义

| 字符 | JS 引擎 | HTML 解析器 |
|---|---|---|
| `//` | 注释 | 两个普通斜杠 |
| `<` | 小于号 | 标签开始 |
| `"` | 字符串引号 / 普通字符 | 属性值边界 |
| `'` | 字符串边界（在 JS 里） | 普通字符 |

> **注释符是方言**：JS `//` · HTML `<!-- -->` · MySQL `-- ` 或 `#` · shell `#`。

### 认 DOM 型的三招

1. 开页面 → 搜一个标记词 → `Ctrl+U` 搜（**搜不到**）→ `F12 Elements` 搜（**有**）
2. `curl` 同一个 URL → `grep -c "标记词"` = **0**
3. payload 放 `#` 后面 → 连请求都不发（`access.log` 里什么都没有）

> 注意差别：payload 放 `?q=` 时，**日志里看得到这次请求**（请求行带完整 URL），只是服务器没把它拼进响应。**「日志看不到」只对 hash 成立。**

### 命令行取证

```bash
# 起玩具靶场
cd ~/day25 && python3 -m http.server 8083

# 证明服务器没发过 payload（应为 0）
curl -s "http://localhost:8083/dom_search.html?q=%3Cimg%20src%3Dx%20onerror%3Dalert(1)%3E" | grep -c "onerror"

# payload 放 hash：浏览器根本不发给服务器
curl -s "http://localhost:8083/dom_hash.html#%3Cimg%20src%3Dx%20onerror%3Dalert(1)%3E" | grep -c "onerror"
```

### Console 三件套（DOM 型必备）

```js
trackSearch.toString()                             // 看函数源码：里面只有变量名，没有我的 payload
var src = '<img src="...' + query + '">'; src      // 看真实的拼接结果
document.body.insertAdjacentHTML("beforeend", src) // 验证这段 HTML 会不会执行
```

### ⚠️ 坑（Day 25 实录）

- **以为 payload 拼进了 JS 源码** → `+ query +` 是**运行时字符串拼接**，payload 只是数据，JS 语法永远合法
- **以为 `//` 能注释 HTML 里的东西** → HTML 不认 `//`，要用 `<!--`
- **把 `;` `)` 塞进 HTML 层** → 那是 JS 语法，在 HTML 层全是废字符
- **`Ctrl+U` 搜得到就断定 Reflected** → Stored 也搜得到，一条判据只能划一条线
- **以为 payload 放 `?q=` 日志就看不到** → GET 参数在请求行里，`access.log` 记得清清楚楚；只有 `#` 后面的才真不发
- **Console 一片红字就以为自己写错了** → 先分清环境噪音（如 `WebSocket is already in CLOSING or CLOSED state.` 是平台自己的）
- **忘了 `document.write` 在页面加载完后调用会清空整个文档**

### 🔎 Day 25 的核心一句话

> **DOM 型 = 服务器发死页面，页面 JS 把「数据」从传送门（`document.write` / `innerHTML`）倒进 HTML 解析器。
> payload 从没当过 JS 源码，所以 Day 24 的转义功夫在这儿用不上，用的还是 Day 23 的标签功夫。**

## Day 26 · 实战任务卡：内部便签站 XSS 审计（Day 16–25 综合）

> 目标不是「多打几个洞」，是**出一份开发能照着改的报告**。
> 昨天会打，今天要会**说准**：哪一格、凭什么、证据在哪。

### 一、五种「格子」总表（判上下文只看这张）

| 格子 | 长什么样 | 要逃什么 | 学会的日子 |
|------|---------|---------|----------|
| **标签之间** | `<h2>数据</h2>`、`<div id='out'>数据</div>` | `<` `>`（能自己开标签） | 21 / 26 |
| **属性值里** | `<input value='数据'>` | **包裹它的那个引号**（`'` 或 `"`） | 23 / 26 |
| **JS 字符串里** | `<script>var a='数据'</script>` | JS 引号 / 反斜杠，或 `</script>` | 24 / 26 |
| **URL 里** | `<a href="page?x=数据">` | `javascript:` 之类协议 | （待学） |
| **HTML 注释里** | `<!-- 数据 -->` | `-->`（先跳出注释） | 26（只认识，没打过） |

> 判格子的唯一正法：**看 payload 前后紧挨着的字符**（`Ctrl+U` 查），不是凭印象往里塞。

### 二、类型 ≠ 上下文（两把尺子，别混）

| 尺子 | 问的是 | 可选值 |
|------|--------|--------|
| **类型**（type） | 数据**从哪来**：经过服务器吗？存过吗？ | `Reflected` / `Stored` / `DOM-based` |
| **上下文**（context） | 数据**落在哪**：哪一格？ | 标签之间 / 属性值里 / JS 字符串里 / URL 里 / HTML 注释里 |

- **DOM 型不是「第六种格子」**，它只说数据来路（浏览器自己读地址栏）；落点照样是五格之一。
- 所以「Stored 型 + 属性值里」「DOM 型 + 标签之间」都合法，两列各填各的。

### 三、取证命令卡（审计报告的证据全靠这几条）

| 命令 | 干什么 | 英文全称 | 记忆钩子 |
|------|--------|---------|---------|
| `curl -sG --data-urlencode "q=..." URL` | **GET** 带参数并**自动 URL 编码**（空格变 `%20`） | **G** = get（把数据拼到 query） | 有空格/特殊字符就靠它，别手写 URL |
| `curl -d "a=1&b=2" URL` | POST 送表单数据 | **d** = data | 只发给 `-X`/默认的 POST |
| `curl -o 文件 -w '%{http_code} %{size_download}'` | 存到文件 + 打印**状态码和大小** | **o**=output，**w**=write-out | 看不到输出时先看这两个数 |
| `curl -sS` | 静默进度条，但**保留错误信息** | **s**=silent，**S**=show-error | 只写 `-s` 会把 `Failed to connect` 一起吞掉 |
| `grep -o "特征串"` | 只打印**匹配到的那一截** | **o** = only matching | 证据要「原样那一行」时用它 |
| `grep -c` | 只打印**命中行数** | **c** = count | 判「有没有」用它，判「长什么样」用 `-o` |

### 四、⚠️「0 命中」必须先排除两种情况

> 看到 `0` 就写「测不出」= 报告造假（哪怕不是故意的）。三种可能：

| 可能 | 排除手段 |
|------|---------|
| ① **请求根本没发出去**（URL 有裸空格 / 参数写错 / `-s` 吞错） | `-S` 看错误 + `-w '%{http_code}'` 必须 **200**（`000` = 没发/没连上） |
| ② 发出去了但**打错门**（404、端口错、服务没起） | 状态码 + 服务器日志里那条请求行 |
| ③ **真的没有**（这才是结论） | 前两条都排除了才写 |

### 五、两类特殊证据

| 类型 | 证据怎么做 | 为什么 |
|------|-----------|--------|
| **存储型** | **两步**：`curl -d` 存（回 `303`，body 为空！）→ 再用**干净 URL** `GET` 读取 + `grep` 落地 | 「存下来 + 原样吐出去」两件事都要有物证 |
| **DOM 型** | **两条**：① `curl` 同 URL（`#` 用 `%3C…%3E` 编码）→ `grep -c` = 0；② 服务器日志只有 `GET /dashboard`、**没有 payload** | 「响应里没有 + 日志里没有」= 服务器全程没收到 |

### 六、⚠️ Day 26 新增的坑

| 坑 | 正确做法 |
|----|---------|
| **请求不带 payload 就 grep** | 等于空手敲门再找自己的脚印。先确认「我这次真把东西送进去了」 |
| **`grep "alert"` 撞到页面自带代码** | 页面自己的 JS 校验里也有 `alert('内容不能包含 <')` → 假阳性。**特征串要长**：`onerror=alert(1)` |
| **URL 里写裸空格** | `curl: (3) URL rejected: Malformed input to a URL function`，一个字节都没发。GET 用 `--data-urlencode`，手写就写 `%20` |
| **未加引号的属性值「吃到哪」** | 一直读到**空白或 `>`**才结束 → `onfocus=alert(1)'` 会把 `'` 吞进值里 → JS 语法错、静默不弹。**payload 末尾那个空格是语法必需的收尾符** |
| **属性名拼错（`onnmouseover`）** | 浏览器**直接忽略、不报错**（和 `heaers`/`Sat-Cookie` 同族）。事件名就 `on` + `mouseover` |
| **只 POST 就 grep 存储型** | `303` 跳转的响应 body 是**空的**，`grep` 必然 0。必须再 `GET` 一次 |
| **参数名抄错**（`name=` 当 `title=`） | 一律**抄** `<input name=...>`；抄错时服务端静默拿不到值，落地里那一栏是空的 |
| **把 `#` 当注释** | `#` 是 **fragment**（Day 12）：浏览器**不发**给服务器，由页面 JS 读 `location.hash`。HTML 注释是 `<!-- -->` |
| **报告「入口」写成「网页源代码搜索」** | 入口 = **页面 + 参数**（`/search?q=` / `/note` 表单的 `content` 字段）；「网页源代码」是你**看的方法** |
| **「漏洞太多」「很重要」当危险度理由** | 只能用三维度：① 受害者要不要配合 ② 影响几个人 ③ 服务端能不能拦 |

### 七、报告三要素（三次任务卡都被打回的那条）

| 要素 | 写成什么样 | 反例 |
|------|-----------|------|
| **发现** | 一句话：哪个入口、什么类型、什么格子 | 「这里有 XSS」 |
| **思路** | 我怎么找到的（输入点→输出点→判前后字符） | 「凭经验」 |
| **依据** | **贴落地原文 + 命令 + 真实输出** | 「见附件」「我以为是这样」 |

## 🧩 常用组合拳（跨 Day 复用）

| 场景 | 命令 |
|------|------|
| 手写一个塞进 URL 的 payload 并验证 | 先写 payload → `unquote_plus` 反解对账 → `echo` 自检 shell → `curl -s -o 文件` → `grep -o` 取证据 |
| 判断一个 lab 的 context | `F12` → Elements 找输入落在哪（标签之间 / 属性里 / `<script>` 里）→ `Ctrl+U` 看服务器原文对照 |
| 分清「编码了没」 | curl 原文里看到 `&lt;` `&quot;` = 已编码；看到 `<` `"` 原字符 = 未编码 |
| 拿 lab 的通关判定 | 先看右上药丸 → 不刷新可能还是 Not solved → `F5` 再看 |
| 判 Reflected 还是 Stored | 关页面重开还弹？→ 看地址栏有没有 payload？→ `curl` 干净 URL 后 `grep` 正文能不能搜到 |
| 找一个功能点的输出上下文 | 先发一条**正常**内容当基线 → `Ctrl+U` 搜它 → 看包着它的标签 |
| 表单里哪个字段能打通 | 逐字段试（comment / name / website 分开试）→ `grep -o` 看谁原样、谁被转成 `&quot;`/`&gt;` |
| 绕过前端限制（长度/格式） | ① 换一个没限制的字段 ② `curl -d` 直接发 ③ F12 删 `maxlength` 属性 ④ 以后：Burp Repeater 改包 |
| 证明「毒在服务器」 | `curl -s` 一个**不带 payload** 的 URL → `grep` 响应正文 → 搜到即铁证 |
| 判「该用哪种注入」 | 看落点：标签之间 → 开新标签；属性值里 → **关门 + 加属性**；JS 字符串里 → **逃 JS 引号**写 JS |
| 让 XSS 零交互触发 | `autofocus` + `onfocus`（或天然失败的 `img src=x onerror=`）；要悬停/点击的 PoC 可信度低一档 |
| 手写 payload 的引号检查 | 三层过一遍：模板引号（关门）/ 属性值引号（成对）/ 值内字符串（单引号） |
| curl「啥都没输出」 | `-sS`（看错误）→ `--http1.1`（HTTP/2 兼容）→ `-w '%{http_code} %{size_download}'`（看状态）→ `wc -c`（看大小）→ 最后才 grep |
| 从页面反推请求长相 | `<form action=... method=...>` + 每个 `<input name=...>` → 路径和参数名**抄**，不猜 |
| 判「是不是 JS 字符串上下文」 | `Ctrl+U` 搜 `var xxx = '` → 输入被包在一对 JS 引号里；`<>` 只是普通字符，要逃的是 JS 引号 |
| 选 JS 字符串的打法 | 数「服务器给哪些字符喂了 `\`」：`'` 和 `\` 全喂 → 换 `</script>`；只喂 `'` → `\';alert(1)//` |
| 验证 payload 真的执行了 | 看弹窗 / Console，**不看 grep**；只在源码里 grep 到 = 等于没验证 |
| 提交前反解 URL 对账 | `python3 -c "...unquote_plus('...')"` 肉眼过 `%3D`/`%3E`、`=`/`(`、括号引号 |
| 判「是不是 DOM 型」 | `Ctrl+U` 搜 payload（搜不到）+ `F12 Elements` 搜（有）→ DOM；再 `curl` 同 URL `grep -c` = 0 佐证 |
| 证明「服务器没参与」 | payload 放 `#` 后面 + `curl` 同 URL → `grep -c` = 0（浏览器不发 fragment） |
| 看页面的真实拼接结果 | Console：`var s = '<前缀' + query + '后缀'; s` → 打印出来逐段读 |
| 判断「是数据还是源码」 | 看落点：在 `'...' + query + '...'` 里 = 数据；被 `echo` 进 `<script>` 源码 = 源码（要算转义） |
| 看页面 JS 到底怎么写的 | Console：`函数名.toString()` → 确认 payload 是在变量值里还是在源码里 |
| 给一个站做 XSS 体检（黑盒） | 入口逐个点 → 记下每个输入点/输出点 → 五格判上下文 → 逐格配 payload → 弹窗/Console 验 → `curl` + `grep` 留证 → 写报告 |
| 证明一条「测不出」的结论 | 先 `http_code=200`（不是 `000`）→ 确认请求**真带了 payload** → `grep` 用长特征串（不用 `alert`）→ 再看服务器日志里有没有 payload |
| 属性注入收尾（值没加引号时） | payload 末尾补一个**空格**，把「值的边界」划出来，否则后面的引号会被吞进值里 |
| 存储型留证 | `curl -d` 存（`303`，body 空）→ `curl` 干净 URL + `grep -o` 落地 → 两步一起才算证据 |
| 报告交前自查 | 每条有没有「发现/思路/依据」→ 上下文是不是五格里的名字 → 危险度理由挂没挂三维度 → 有没有把页面自带 JS 当假阳性 |
