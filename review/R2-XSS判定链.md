## 开课先补三个词（各一句）

| 词 | 是什么 | 住在哪 | 干什么 |
|---|---|---|---|
| **source** | 能读到「用户说了什么」的地方 | 前端 `location.search` / `location.hash` / `input.value`；后端 `$_GET` / `$_POST` | 只决定「这句话是谁说的」 |
| **sink** | 会把字符串当**代码/HTML** 交给解析器的地方 | `innerHTML` / `document.write` / `eval` / `href` | 决定「这句话落进哪一格」 |

# 块 1 / 3 · 反射型是「镜子」（508）

## 镜子模型

```
你在网址里说一句  →  服务器把它抄进返回的 HTML  →  浏览器把那段 HTML 当页面解析
```

「反射」= 服务器**原样把话复读回来**。所以反射型**一定经过服务器**——不经过服务器的是 DOM 型。

## 判据：三问（不用背类型名，按顺序问）

1. **我的字出现在服务器返回的 HTML 里吗？**
   查法：`curl -s "http://靶场/页?q=TEST123" | grep TEST123`（或者右键 Ctrl+U 搜）
2. **它落在哪一格？** 正文 / 属性值 / `<script>` 里 / URL
3. **那一格里，我的字符还算不算语法？**（`<` 是不是标签、`'` 是不是关门）

## 示范（完整走一遍）

页面 `/greet?name=` 拼出：

```html
<h1>Hello, [你输入的东西]</h1>
```

- 输入 `Tom` → `curl` 里能搜到 `Tom` → **经过服务器** ✅
- 输入 `<b>x</b>` → 页面显示**加粗的 x** → `<` 被当标签 → 第 3 问答「算语法」
- 输入 `<b>x</b>` 若显示成字面的 `<b>x</b>` → `<>` 被 HTML 编码 → 这个格子堵住了

## 练习 1（4 小问，一句一句答）

1. 打开 `/greet?name=Tom`，Elements 里是 `<h1>Hello, Tom</h1>`，`Ctrl+U` 源码里也能搜到 `Tom`。换成 `name=<b>x</b>` 页面显示**加粗的 x**。这属于哪种 XSS？依据是哪个环节？
2. `/greet2?name=Tom`：`Ctrl+U` 里**搜不到** `Tom`，但 Elements 里是 `<h1>Hello, <span id="out"></span></h1>`，页面 JS 做了 `document.getElementById('out').innerHTML = ...location.search...`。这属于哪种？**服务器参与了吗？**
3. 留言板提交 `hello`，刷新后**所有访客**的页面上都有。这属于哪种？你查了哪两个动作才敢这么说？
4. 一句话：反射型和 DOM 型最容易混的地方，差在**哪个环节**？

# 块 2 / 3 · JS 字符串格：三个入口（515 + 516）

## 场景长这样

```html
<script>
  var s = '你输入的东西';
  document.getElementById('out').textContent = s;
</script>
```

这个格子里，**HTML 标签没用**（`<img>` 只是几个普通字符），浏览器只在这里找一件事：`</script>`。
所以要逃的是 **JS 的语法字符**。

## 三个入口（每个都有前提）

| 入口 | 怎么用 | 前提（服务端漏了哪一步） |
|---|---|---|
| ① 引号关门 | 打一个 `'` 让字符串提前结束，后面写 `;要执行的代码//` | 引号**没被转义/编码** |
| ② 反斜杠抵消 | 利用 `\` 只吃**紧跟的一个**字符 | `\` **没被转义** |
| ③ `</script>` 掀桌 | 直接把整个 `<script>` 关掉，后面写 HTML | `<` `>` **没被 HTML 编码** |

## 我自己实测的证据（`node review/r2-escape-demo.js`，✅ 已跑，真实输出）

| 源码 | 结果 | 说明 |
|---|---|---|
| `'it\'s'` | `"it's"` | `\` 吃掉紧跟的那个 `'`，它就成了普通字符 |
| `'a\\b'` | `"a\b"` | 两颗反斜杠**互吃**，剩一个真反斜杠，**谁都不保护** |
| `'abc\'` | `SyntaxError: Invalid or unexpected token` | 反斜杠吃掉了收尾引号 → 字符串永远不结束 |
| 只转义引号 + 输入 `\';globalThis.hit=1//` | **`hit = 1`（执行了）** | 服务端的 `\'` 被自己的 `\` 抵消，`\\` 收尾后代码区打开 |
| 引号和反斜杠都转义 + 同一输入 | `hit = 0`（没执行） | 两个都转义时，`\'` 就真的只是内容 |

**第 3 行的坑（Day 24 我连错 3 次的同一个坑）**：源码里 grep 到 payload **≠** 它跑得起来。
判据永远是「有没有执行」，不是「长得像不像」。

## 练习 2（4 小问）

服务端把输入塞进 `<script>var s = '____';</script>`，四种过滤：

| 组 | 服务端做了什么 |
|---|---|
| **A** | 只把 `'` → `\'`；`\` 不管；`<>` 不管 |
| **B** | `'` → `\'` **且** `\` → `\\`；`<>` 不管 |
| **C** | 只把 `<>` → `&lt;&gt;`；引号、反斜杠都不管 |
| **D** | 三样全处理 |

各答一句：**这条能不能出去？走哪个入口？** 写个思路就行，不用完美 payload。
再答一句：**D 这种情况还剩什么路？**

# 块 3 / 3 · source ≠ sink，类型 ≠ 上下文（522 + 530）

## 一句话原则

> **落进哪个格子，由 sink 决定，不由 source 决定。**
> source 只管「这句话是谁说的」；sink 决定「这句话被送到哪个解析器面前」。

常见清单：

- **source**：`location.search` · `location.hash` · `document.URL` · `document.referrer` · `input.value` · `window.name`
- **sink**：`innerHTML` · `outerHTML` · `document.write` · `insertAdjacentHTML` · `eval` · `setTimeout("字符串")` · `href` / `src`（`javascript:`）

## 类型 ≠ 上下文

- **三种类型**（反射 / 存储 / DOM）讲的是：**数据从哪来、存多久**。
- **能不能执行**只看：**它落进哪一格 + 那格的语法有没有被挡住**。

所以「存储型」不等于「一定能执行」；「反射型」也不等于「一定不能存」。

## 练习 3（3 小问）

1. 标出三样东西（source / sink / 落在哪一格）：
   ```js
   const q = new URLSearchParams(location.search).get('q');
   document.getElementById('out').innerHTML = '<p>' + q + '</p>';
   ```
2. 六个点分类（source 还是 sink）：`location.hash` · `innerHTML` · `document.referrer` · `document.write` · `input.value` · `eval`
3. 判断对错 + 一句理由：「这是存储型 XSS，所以一定能执行。」
