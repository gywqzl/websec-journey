- **日期**：2026-10-21
- **靶场**：本地玩具靶场 `js_demo.py`（8082）+ PortSwigger Web Security Academy
- **Lab**：`Reflected XSS into a JavaScript string with single quote and backslash escaped`（Apprentice 学徒档）
- **题目要求**：搜索功能存在反射型 XSS，输入被反射进一个 JavaScript 字符串；单引号和反斜杠都被转义。要求跳出字符串并调用 `alert`。

## 一、第三种格子：JS 字符串

```html
<script>
var searchTerms = '我的输入';
</script>
```

- `<script>` 内部**换了一台解析器**：HTML 那套标签规则全部失效，`<img>` 在这里只是 6 个普通字符。
- JS 解析器在字符串里只认两件事：字符串从哪儿开始、到哪儿结束。开始是 `'`，结束是**下一个没被吃掉的 `'`**。
- 所以这一格：`<` `>` `"` 全是普通字符，**只有 `'` 和 `\` 有权力**。

## 二、核心模型：`\` 会「吃掉」下一个字符

解析器脑子里两句话：

> ① 吃到 `\` → 必须再多吃紧跟的一个字符，两个一起变成**一个普通字符**。
> ② 吃到 `'` 且前面没有 `\` 领着 → **字符串结束**。

| 源码里写的 | 怎么吃 | 内容是什么 |
|---|---|---|
| `\'` | `\` + `'` | 一个普通 `'` |
| `\\` | `\` + `\` | **一个普通 `\`** |
| `\\\'` | 两对，各吃各的 | `\'` 两个字符 |

**关键结论**：`\\` 并不"保护"后面的东西。它俩互相吃掉、变成内容里的一个反斜杠，然后就耗尽了。

字数验证（Console）：`'a\\b'.length` = **3** —— 源码 4 个字符，内容只有 3 个。

## 四、payload 与为什么生效

```
</script><script>alert(1)</script>
```

为什么：

1. **字符串路线是死的** —— 服务器给每一个 `'` 都喂了一颗 `\`（`'` → `\'`），也给每一个 `\` 加了盾（`\` → `\\`）。自带 `\` 去顶盾也没用：`\` + `'` 变成 `\` `\` `\` `'`，前两颗互吃、后两颗互吃，那个 `'` 还是被吃掉了。
2. **所以不逃了，掀桌子** —— `</script>` 直接把整个 `script` 元素关掉，后面的输入就落在 HTML 地面上，可以重新开一个 `<script>`。
3. **残留物无害** —— 原模板尾巴上的 `';` 会变成页面上的文字。

## 五、证据

### 5.1 lab 判定

`LAB Not solved` → 弹窗 → 刷新 → `LAB Solved`

### 5.2 侦察结果（本地 8082）

| 我输入 | 落地 |
|---|---|
| `hello` | `var searchTerms = 'hello';` |
| `it's` | `var searchTerms = 'it\'s';` ← 单引号被喂了 `\` |
| `a\b` | `var searchTerms = 'a\\b';` ← 反斜杠被加了盾 |
| `<` | `var searchTerms = '<';` ← **没编码** |
| `"` | `var searchTerms = '"';` ← **没编码** |

### 5.3 同一个响应里的两格，待遇不同（就是"输出编码要按上下文"的铁证）

```bash
curl -s --get --data-urlencode "q=<" http://localhost:8082/js | grep -o '<b>.\{0,12\}'
curl -s --get --data-urlencode "q=<" http://localhost:8082/js | grep -o "searchTerms = .*"
```

- HTML 那一格（`<b>`）→ `&lt;`（编码了）
- JS 那一格（`<script>`）→ `<`（原样）

**同一个服务器、同一份输入、同一个请求，两格两种待遇。** 编码方式必须跟着"这段数据要插到哪儿"走。

## 六、复盘：今天最贵的两个教训

1. **教练连着给错两次 payload**，根因都一样：只验证了"payload 落在源码里的长相"，就当它能执行。
   → **判据永远是弹窗 / Console，不是 `grep`。源码里有 payload ≠ 它被执行。** 这是真实测试里的头号误报来源。
2. **我自己手滑把 `alert(1)` 写成 `alert=(1)`**，而且它**不报错**——是赋值不是调用。地址栏反解一眼就能看出来。

## 七、我实际卡住的

1. 把 `alert()` 写成了 `alert=`。它不报错、Console 也不红，就是不弹，我还以为自己 payload 思路错了。后来是在地址栏把 `%3D` 反解出来，才发现就差这一个字符。
2. 我一度以为是自己写的 `//` 把后面的东西注释掉了。后来才搞清楚：`//` 只在 JavaScript 里有效，管不到 `</script>` 这个 HTML 标签——那次真正的问题从头到尾就是那个 `=`。

## 八、我学到了什么（费曼）

今天学了怎么把 payload 写进 JS 代码里，有两种办法：

1. 如果 `'` 没被转义（没被喂 `\`），就先关门，再在后面直接写 JS。
2. 如果 `'` 被转义了（关不上门），就不再从字符串里出去，而是用 `</script>` 把整个 script 关掉，重新开一个 `<script>` 把代码写进去执行。
