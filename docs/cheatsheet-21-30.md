## Day 21 · PortSwigger Web Security Academy 入门 + 第一个官方 lab

### 平台名词卡（不是命令，但天天要用）

| 名词 | 意思 | 记忆钩子 |
|------|------|---------|
| PortSwigger | 做 **Burp Suite** 的英国公司，Web 安全学院是他们的免费靶场 | Burp = 打嗝，渗透测试的标配抓包工具 |
| Web Security Academy | 免费官方靶场，题目叫 **lab**，分难度三档 | academy = 学院 |
| lab 题目页三块 | **background**（坏在哪）/ **objective**（`To solve the lab, ...` 做到啥）/ hints·Solution（折叠框） | objective = 目标，先读它 |
| Apprentice / Practitioner / Expert | 学徒 / 实践者 / 专家 三档难度 | apprentice = 学徒（Day 21 打的就是这档） |
| **context**（上下文） | 你的输入被塞进 HTML 的**哪个位置**：标签之间 / 属性里 / `<script>` 里 | context = 语境；**位置决定 payload 怎么写** |
| **nothing encoded**（未编码） | 服务器把输入**原样**拼进页面，没做任何转义 | encoded = 编码过；「没有」= 原样放行 |
| Solved 横幅 | 右上绿药丸 `LAB Solved` | 平台在页面里 hook `window.alert`，调用才判分；**不刷新可能还显示 Not solved** |

> **靶场工作流（今天立的规矩）**：
> 读题 → 找输入点（`name=xxx`）→ 判上下文 → 自己造 payload → 看现象 → 拿 Solved → 写 writeup

### curl 发带参数的 GET / 取证据

| 命令 | 干什么 | 英文全称 | 记忆钩子 |
|------|--------|---------|---------|
| `curl -s 网址` | **静默**：不打印进度条（只出正文） | **s**ilent | silent = 安静 |
| `curl -s -o 文件 网址` | 把响应**存成文件**（之后随便查） | **o**utput | out = 输出到文件 |
| `grep -o "关键词.\{0,20\}" 文件` | **只打印**匹配到的那一段（前后各 20 字符） | **o**nly matching | only = 只留匹配的 |
| `grep -n "关键词" 文件` | 打印整行 + 行号 | **n**umber | number = 行号 |
| `curl -G -d "search=x" 网址`（选学） | 把数据**拼到 URL 的 query** 上（GET 用） | **G**ET | `-G` 走 GET |
| `curl --data-urlencode "search=<x>"`（选学） | **自动替你做 URL 编码** | — | 「替你做 % 转义」 |

> ⚠️ **同一个字母，两个工具两个意思**：`curl -o` = **output 存文件**；`grep -o` = **only matching 只打印匹配**。别混。

### URL 编码对照（手写 payload 必背）

| 原字符 | 编码 | 说明 |
|--------|------|------|
| `<` | `%3C` | 开标签的钥匙 |
| `>` | `%3E` | ⚠️ 和 `%3D`（`=`）只差一个字母，**ASCII 里 0x3D/0x3E 挨着**（D 在 E 前、`=` 在 `>` 前） |
| `"` | `%22` | 双引号（`alert("Q")` 要它） |
| `'` | `%27` | 单引号 |
| `(` `)` | `%28` `%29` | 函数括号 |
| `=` | `%3D` | 等号（也常用在 `name=value` 里，query 分隔符除外可不编） |
| 空格 | `+` 或 `%20` | query 里 `+` 就是空格（`unquote_plus` 才认它） |
| `%` | `%25` | 百分号自己 |

### 两个自检习惯（Day 21 最大的收获）

| 什么时候 | 敲什么 | 为什么 |
|---------|--------|--------|
| 拼**长命令 / 带特殊字符**的命令前 | `echo "你的那串东西"` | 先看 **shell 解析后真正送出的是什么**（引号、`<` `>` 有没有被吃掉） |
| 手写完 URL 编码后 | `python3 -c "from urllib.parse import unquote_plus; print(unquote_plus('...'))"` | **反解对账**：解出来和你原本想写的是不是同一句 |

> 三层解析要分清：**shell（引号/重定向）→ URL 编码（URL 允许哪些字符）→ JS 语法（要不要引号）**。
> 一个字符之差 = 「能执行」和「报错」之差。

### ⚠️ 坑（Day 21 实录）

- **`"` 直接写在 curl 的双引号里** → 被 **shell** 吃掉 → payload 退化成 `alert(Q)` → `ReferenceError: Q is not defined` → **不弹窗**（与 Day 20 `alert(Qzl)` 同族，只是这次是 shell 干的）。
  → 解药：`"` 编码成 `%22`，URL 里就没有真引号了，外层双引号才安全。
- **`%3D` 当 `%3E` 用** → `<img ...>` 没闭合，浏览器把后面的 `'</h1>` 也吞进属性值 → `onerror=alert("Q")=` → `SyntaxError`。
- **`onerror.("Q")`（把 `=` 打成 `.`）** → 处理函数名不对，事件不触发。
- **弹窗没出现 ≠ 没执行** → `F12` → **Console** 看红字（Day 20 同款）。
- **横幅 Not solved ≠ 没解开** → 钩子已上报，等 5–10 秒或 `F5` 刷新再看。
- **lab 页面的 Solution 折叠框**：做题时别点，自己解出来才算数。
- **curl 看到的 ≠ 浏览器看到的**：curl 拿到的是**服务器原文**（标签未被解析），浏览器给的是**解析后的成品**。写报告时两个视角都要。
- **注册账号只影响"记录进度"**，不影响能不能打 lab（官方原话：access everything for free, track progress by creating an account）。

### 🔎 Day 21 的核心一句话

> **上下文（context）决定 payload 怎么写；`nothing encoded` 决定了「原样放行」——两个条件同时成立，才有 XSS。**
> 防御加在**输出层**：`<` 变 `&lt;` 之后，浏览器只会把 payload「念」给用户看，不执行。

## Day 22 · 存储型 XSS（Stored XSS）：一次投放，全员中招

### 三种 XSS 对照（考试/报告都用这张）

| | **Reflected**（反射型） | **Stored**（存储型） | **DOM-based**（DOM 型） |
|---|---|---|---|
| 数据存不存 | 不存，当场回显 | **存进服务器**（数据库/文件） | 不经过服务器，页面 JS 自己读自己写 |
| 谁中招 | 点了那条链接的人 | **所有访问该页面的人**（含管理员） | 点了那条链接的人（但毒在执行发生在浏览器） |
| 证据在哪 | URL 的 query 里 | **响应正文里** | 只有 F12 Elements 有，`Ctrl+U` 搜不到 |
| 修的时候 | 输出编码 | 输出编码 | **改 JS**（别用 `innerHTML`，用 `textContent`） |

### 两个必须分清的"点"

| 名词 | 人话 | 今天的例子 |
|---|---|---|
| **输入点**（input point / entry point） | 数据**塞进去**的地方 | 评论表单 4 个字段：comment / name / email / website |
| **输出点**（output point / sink） | 数据**吐出来**、拼进 HTML 的地方 | 文章页的评论列表 |

> **输入点 ≠ 输出点**：Stored 型的这两个点**不在同一个请求、不在同一个页面**里。这就是它和 Reflected 的结构差别。

### 判断 Stored 的三招（写报告就靠这三句）

| # | 动作 | 如果是 Stored |
|---|---|---|
| 1 | 关掉页面重开 / 换无痕窗口 / 换浏览器 | 照样弹 |
| 2 | 看地址栏 | **干净**，不带 payload |
| 3 | `curl` 请求干净 URL → `grep` 响应正文 | 正文里**能找到** payload |

> 「有输入点」≠「存储型」。搜索框也有输入点，但通常是 Reflected。
> 判据只有一条：**数据有没有被存下来？输出点是不是在另一个请求里？**

### 取证命令

| 命令 | 干什么 | 说明 |
|------|--------|------|
| `curl -s "网址/post?postId=10" -o /tmp/post.html` | 请求一个**干净的 URL**，把响应存下来 | `postId` 是文章编号，从文章页 URL 抄 |
| `grep -o "onerror.\{0,30\}" /tmp/post.html` | 在响应正文里搜 payload | 搜到了 = 服务器在发毒 = Stored |

### 三层「限制」，谁在拦你？

| 层 | 写在哪 | 例子 | 谁执行 | 能绕吗 |
|---|---|---|---|---|
| ① 输入框属性 | HTML 标签上 | `maxlength="10"`、`required` | **浏览器** | ✅ F12 删 / `curl -d` 直接发 |
| ② 页面 JS 校验 | `<script>` 里 | `if (含"<") alert("不许")` | **浏览器** | ✅ 不执行 JS / 改 JS |
| ③ 服务端代码 | PHP/Python，看不见 | `if (strlen($name) > 10) die();` | **服务器** | ❌ 只能找逻辑漏洞 |

> 判据一句话：**这段代码在哪跑？浏览器里 → 攻击者可改；服务器上 → 改不了。**
> 所以 **XSS 的正解只能做在 ③**：输出编码。前端过滤 = 只锁住你自己的浏览器。

### 两个模型（今天最有价值的两句）

> **表单只是「填表助手」**：帮你把内容拼成一个请求发出去。
> **服务器只相信「收到的那个请求」**，从不回头看页面上的表单。
>
> **curl 不管表单长什么样，但必须遵守服务器的数据契约**（字段名 `name=value` 写错 = 丢字段）。

### ⚠️ 埋雷：`type="hidden"` 不是安全措施

```html
<input type="hidden" name="role" value="user">
```

浏览器里看不见，但**会被提交**；服务器要是直接信了 → 改成 `role=admin` 就是越权。
→ 阶段二的 **IDOR / 越权 / 业务逻辑漏洞** 全从这里起。

### HTML 实体（entity）对照 —— 服务器做输出编码时干的事

| 原字符 | 实体 | 说明 |
|--------|------|------|
| `<` | `&lt;` | 标签开不出来了 |
| `>` | `&gt;` | 标签关不上了 |
| `"` | `&quot;` | 引号逃不出属性了 |
| `'` | `&#39;` | 同上（单引号版） |
| `&` | `&amp;` | 和号本身 |

> 在 `curl` / `Ctrl+U` 里看到 `&lt;` `&quot;` = **这个字段做了编码**；看到原字符 = **nothing encoded**。
> 同一个表单，不同字段的处理**可以不一样** —— 必须逐字段试。

### F12 Elements vs Ctrl+U（证据铁律）

| | 看到什么 | 用来干嘛 |
|---|---|---|
| **`Ctrl+U`** | 服务器发来的**原始字节** | **取证**（判断有没有编码、payload 在不在正文里） |
| **F12 Elements** | 浏览器解析后、**活着的 DOM**（被 JS / 扩展 / 翻译插件改过） | 定位结构、看执行结果、Console 看报错 |

> ⚠️ 见过 `<font _msthash=... _msttexthash=... _mstmutation=...>` 吗？`mst` = **Microsoft Translator**（Edge 翻译功能）注入的，`_istranslated="1"` 直接告诉你这是译文。**不是网站写的**，别写进报告（真实误报来源）。
> 做靶场/取证前先关掉自动翻译。

### ⚠️ 坑（Day 22 实录）

- **把 F12 Elements 当源码** → 看到 `_mst*` 一堆莫名属性，以为网站有问题。取证一律 `Ctrl+U` / `curl`。
- **只试一个字段就下结论** → comment 原样输出能打通，name 被编码打不通；**同一表单逐字段试**。
- **`alert(Qzl)` 少引号**（第 2 次）→ `ReferenceError: Qzl is not defined` → 不弹窗；判据看 F12 Console。
- **以为"有输入点就是存储型"** → 搜索框也有输入点，是 Reflected。判据是「有没有存下来」。
- **以为前端 `maxlength` / JS 校验是修复** → 只锁浏览器；`curl -d` 直接发就绕过去了。
- **想靠"过滤输入"修 XSS** → 黑名单永远漏、富文本还要 `<`；正解是**输出编码**。

### 🔎 Day 22 的核心一句话

> **毒存在服务器上，URL 干干净净也能中招；判 Stored 看三样——重开还弹、URL 干净、正文里有 payload。**
> **修复永远做在服务端输出层：数据怎么存都行，吐进 HTML 的那一刻按位置转义。**

## 🧩 常用组合拳（跨 Day 复用）

| 场景 | 命令 |
|------|------|
| 手写一个塞进 URL 的 payload 并验证 | 先写 payload → `unquote_plus` 反解对账 → `echo` 自检 shell → `curl -s -o 文件` → `grep -o` 取证据 |
| 判断一个 lab 的 context | `F12` → Elements 找输入落在哪（标签之间 / 属性里 / `<script>` 里）→ `Ctrl+U` 看服务器原文对照 |
| 分清「编码了没」 | curl 原文里看到 `&lt;` `&quot;` = 已编码；看到 `<` `"` 原字符 = 未编码 |
| 拿 lab 的通关判定 | 先看右上药丸 → 不刷新可能还是 Not solved → `F5` 再看 |
| 判 Reflected 还是 Stored | 关页面重开还弹？→ 看地址栏有没有 payload？→ `curl` 干净 URL 后 `grep` 正文能不能搜到 |
| 找一个功能点的输出上下文 | 先发一条**正常**内容当基线 → `Ctrl+U` 搜它 → 看包着它的标签 |
| 表单里哪个字段能打通 | 逐字段试（comment / name / website 分开试）→ `grep -o` 看谁原样、谁被转成 `&quot;`/`&gt;` |
| 绕过前端限制（长度/格式） | ① 换一个没限制的字段 ② `curl -d` 直接发 ③ F12 删 `maxlength` 属性 ④ 以后：Burp Repeater 改包 |
| 证明「毒在服务器」 | `curl -s` 一个**不带 payload** 的 URL → `grep` 响应正文 → 搜到即铁证 |
