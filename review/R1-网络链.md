## 三类监听地址

| 看到什么 | 谁能连 | 例子（我这台） |
|---|---|---|
| `127.0.0.1:端口` | 只有本机 | `127.0.0.1:3306`（MySQL） |
| `*:80` | 本机所有网卡，同网络的人能连 | `*:80`（Apache） |
| `某块网卡的 IP:端口` | 走那块网卡的人 | `10.255.255.254:53` |

实测对比（同一条命令，只换地址）：

```
$ curl -s -o /dev/null -w "%{http_code}\n" http://192.168.221.59/       -> 200
$ curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3306/       -> 000
```

3306 只听 `127.0.0.1`，所以换成 eth0 的地址就连不上。

## `curl -v` 的行首三种

```
*   Trying 127.0.0.1:80...            <- curl 自己的旁白
> GET / HTTP/1.1                      <- 我发出去的
> Host: 127.0.0.1
> User-Agent: curl/8.18.0
> Accept: */*
>                                     <- 空行：告诉服务器「头结束了，下面是请求体」
< HTTP/1.1 200 OK                     <- 服务器回来的
< Server: Apache/2.4.66 (Ubuntu)
```

`-v` 的这些行走的是 stderr，所以想截取要写 `2>&1`，不然管道收到 0 字节。

## 今天纠正的三个说法

1. `HTTP/1.1` 是**协议版本**，不是我用的工具（工具是 curl，写在 `User-Agent` 里）
2. `Host` 是**我要访问的网站名**，不是我这边的地址
3. `User-Agent` 是**客户端自报身份**，不是「代理」（proxy 是中转服务器）

## 0.0.0.0 为什么不能当网址

`0.0.0.0` 是监听时的**占位符**，代替「本机所有地址」，管的是「我在哪个本地地址上收」，
不管「谁能来敲门」——那是网段、路由、防火墙的事。

地址本来是要唯一指向一台机器的，而 `0.0.0.0` 在**每台机器上都指它自己**，
写进网址别人只会打到他自己那儿，所以它不能当网址用。

坑：本机 `curl http://0.0.0.0/` 会回 200，因为本机把它当 `127.0.0.1` 处理了。
**能通 ≠ 成立。**

## 我实际卡住的

今天没搞懂 0.0.0.0 具体的作用以及网卡和 ip 的关系，不过在研究和询问下都解决了，0.0.0.0 是一个通配地址或者说是占位符，意思是囊括本机上的任意地址。网卡相当于一栋楼的大门，而 ip 是这栋楼的门牌号，端口是里面的房间号。
